# Product

## Platform

web

## Users

Дизайнеры и арт-директора, которым нужен стартовый концепт: человек садится за новый проект и не хочет начинать с пустого листа. Сценарий — короткая сессия «покидать варианты» на ноутбуке, часто в начале работы или между задачами; решение принимается за секунды, а не в результате изучения каталога. Второй, служебный пользователь — тот же дизайнер в роли редактора собственного набора данных.

## Product Purpose

Одностраничный генератор идей: выдаёт случайную комбинацию «ниша + настроение + название бренда + палитра» и служит отправной точкой для нового концепта. Успех — комбинация, которую хочется немедленно развивать: она достаточно конкретна (ниша и имя), достаточно свободна (настроение и цвета) и не повторяет предыдущую.

## Positioning

Механизм, который соседний продукт не скопирует правдой: не библиотека референсов, не генератор логотипов и не moodboard-сервис, а один такт «прокрута» четырёх независимых измерений сразу. Ценность в подборе пары «узкая ниша + настроение + имя + палитра», а не в каждом отдельном списке: ни один из четырёх слотов по отдельности не является продуктом.

## Operating Context

- Работа в браузере на десктопе — основной сценарий; планшет и телефон — вторичные, но обязательные.
- Генерация — короткий ритуал: одно нажатие, короткая анимация прокрута, готовый результат на экране. Повтор — тоже одно нажатие.
- Результат уносят из продукта: имя и HEX-коды копируются в макет, в бриф или в переписку; копирование HEX — часть рабочего процесса, а не украшение.
- Набор данных живёт отдельно (`data/vibedeck.json`) и редактируется собственной страницей-редактором; пополнение списков — регулярная практика владельца.
- Данные читаются `fetch`-ем, поэтому нужен локальный сервер (`python -m http.server 5173`), а не `file://`.

## Capabilities and Constraints

- Четыре слота: `01 / Niche` (категория + ниша), `02 / Mood` (настроение), `03 / Name` (короткое имя латиницей), `04 / Colors` (палитра 2–6 цветов с именами и HEX, плюс имя палитры).
- Одна кнопка `Крутить` — единственный элемент управления; кнопок по слотам нет. Пока идёт прокрут, кнопка неактивна; комбинация готова после остановки последнего слота.
- Прокрут запускает все четыре слота сразу; значения сменяются быстрыми срезами, слоты останавливаются не строго синхронно. Новое значение не повторяет текущее, если в наборе есть альтернативы.
- Последняя комбинация восстанавливается при следующем заходе. Иного сохранения нет: ни избранного, ни истории, ни кнопки «Сохранить». Если сохранённое состояние отсутствует или невалидно — показывается первая случайная комбинация без анимации.
- Итоговая комбинация — это сами слоты; отдельного блока-дубля результата нет. Палитра показывается цветными плашками с именем палитры.
- Клик по цветовой плашке копирует HEX; лёгкий тост подтверждает. Отдельной кнопки копирования нет.
- Все варианты — в `data/vibedeck.json`, ничего не хардкодится в разметке. Структура `{ version, slots: [ { id, label, type, items } ] }`, `type: "list" | "palette"`; порядок слотов в файле = порядок на экране, номер `01…04` выводится из порядка. Новый слот — ещё один объект; новый тип рендера — запись в реестре «слот → рендер» без переписывания прокрута.
- Стек зафиксирован: чистый HTML + CSS, без фреймворков, сборщиков, зависимостей и Tailwind; JavaScript только для механики (прокрут, чтение JSON, последняя комбинация, копирование).
- Нет логотипа и навигации: страница начинается со служебной строки `VIBEDECK / инструмент` и заголовка.
- Раскладка: четыре слота строками-регистрами на всех ширинах; на телефоне — один столбец.

## Brand Commitments

- Название продукта — `VIBEDECK`; пишется латиницей, капсом в служебных подписях.
- Язык интерфейса — русский: заголовок, описание, кнопка, подсказки, тосты, пустые состояния. Латиницей остаются названия слотов `Niche / Mood / Name / Colors`, их номера `01…04`, имена брендов, названия палитр и цветов, HEX.
- Визуальное направление, выбранное заказчиком: швейцарский макет (Neue Grafik) — белый лист, чёрный текст, волосяные линейки, один красный акцент, крупная сжатая типографика Inter Tight и строки-регистры. Сгенерированная палитра — главный цвет на экране; интерфейс с ней не конкурирует.
- Прямые запреты: никаких SaaS-админок, стоковых иллюстраций, градиентных «AI»-клише.
- Исходный референс интерфейса от заказчика: `references/vide-deck-reference.jpg` — четыре колонки с крупной сжатой типографикой, служебные подписи слотов сверху, чёрная кнопка с разрядкой. Служил отправной точкой; итоговое направление — швейцарский макет.

## Evidence on Hand

- `data/vibedeck.json` — реальный набор: 4 слота, 40 ниш, 12 настроений, 24 названия, 16 палитр.
- `editor.html`, `css/editor.css`, `js/editor.js` — работающий редактор данных; задаёт фактический тон служебного интерфейса.
- `css/base.css` — действующие токены, типографика и контролы, общие для обеих страниц.
- `references/vide-deck-reference.jpg` — единственный визуальный референс; он про композицию и типографику главного экрана, а не про готовый дизайн-системный файл.
- Отсутствует и не должно выдумываться: отзывы, клиенты, метрики, тарифы, юридические тексты. Продукт бесплатный и локальный, без аккаунтов.

## Product Principles

1. Один жест. Весь продукт — нажатие `Крутить`; каждый новый элемент управления обязан доказать, что без него нельзя обойтись.
2. Случайность как материал. Ценность в неожиданной комбинации, поэтому прокрут должен ощущаться как бросок, а не как загрузка данных.
3. Результат важнее интерфейса. Палитра и имена — цвет и содержание экрана; «хром» приложения остаётся нейтральным.
4. Данные отдельно от вида. Любой набор пополняется через JSON и редактор без правки страницы.
5. Возврат без потерь. При повторном заходе на экране уже стоит рабочая комбинация — пустого состояния не существует.

## Accessibility & Inclusion

- Один орган управления на странице, доступный с клавиатуры; видимый фокус сохраняется (в проекте уже принят `:focus-visible` на базовом слое).
- Цвет никогда не единственный носитель смысла: у каждой плашки есть название цвета и HEX, у палитры — имя.
- Копирование подтверждается текстовым тостом с `role="status"` и `aria-live="polite"`.
- Контраст текста на кремовой основе — не ниже AA; крупная типографика не заменяет контраст мелким подписям.
